## Что сделано

- `forge_v2` записывается через [diary-storage.js](../app/src/main/assets/diary-storage.js). При отказе записи интерфейс восстанавливает последнее записанное состояние. Сохранение подхода, заметки, фото, еды и цели завершается до сообщения об успехе. Повреждённую запись можно экспортировать как исходный файл. Обычная запись и отправка в облако блокируются до восстановления.
- Импорт JSON проверяет профиль, планы, тренировочные подходы, черновики, питание, рецепты и историю Nutrition Coach. После проверки приложение предлагает подтвердить замену текущих данных. Формат `forge_v2`, origin WebView, схема Room и пользовательские идентификаторы сохранены. Замеры удержаний в секундах исключены из расчётного 1ПМ.
- Удаление облачной копии использует проверяемую ревизию. После выхода или смены аккаунта незавершённый ответ прежнего сеанса не обновляет состояние нового. [delete-account](../supabase/functions/delete-account/handler.mjs) запрашивает подтверждение, проверяет сессию, удаляет идентификатор из Supabase Auth и обрабатывает временные ошибки. Локальный дневник очищается отдельной командой.
- Страницы [Конфиденциальность](https://ermakovnikita58-png.github.io/training-calculator-android/privacy.html) и [Удаление аккаунта](https://ermakovnikita58-png.github.io/training-calculator-android/account-deletion.html) опубликованы через GitHub Pages. Обе возвращают HTTP 200. Точный URL удаления добавлен в разрешённые адреса проекта Supabase. Страница поддерживает пароль и OAuth Google с PKCE, токен сессии хранится в памяти страницы.
- Debug, бесплатные варианты для Google Play и RuStore и ручной процесс подписи разделены. Платёжные SDK остаются в магазинных Debug-вариантах. Health Connect доступен в Debug для тестирования, разрешения удалены из Release. Автоматическая отправка диагностики и аналитики требует настроенного проекта и отдельного согласия.

GitHub Actions подписывает старую и новую сборки одним ключом конкретного runner. В `baseline-origin.txt` указан исходный файл или исходный коммит каждой проверки. Перед и после обновления сверяются упражнения, фото, активная тренировка, завершённые подходы, программы, питание, рецепты, циклы и измерения. ### Безопасность и облако

- AndroidX WebMessageListener проверяет точный HTTPS origin локальных ресурсов и главный фрейм. Внешние страницы открываются в браузере. Прямой файловый доступ и смешанный контент отключены. CSP ограничивает загрузку ресурсов. Существующие inline-обработчики остаются частью WebView, импортированные строки экранируются в шаблонах.
- Токен Google обменивается в нативном коде. Сессия Supabase хранится через Android Keystore. Публичный ключ Supabase и Google Web Client ID предназначены для клиента. `service_role` используется только в Supabase Edge Runtime.
- `forge_snapshots.user_id` связан с `auth.users.id` через `ON DELETE CASCADE`. RLS проверяет `auth.uid()` при чтении, вставке, изменении и удалении. Сервер увеличивает `revision` транзакционно. Одновременное обновление или удаление с прежней ревизией не заменяет текущую запись. [SQL](../supabase-schema.sql) · [Миграция ревизий](../supabase/migrations/20261110000000_snapshot_revision.sql)
- Используется связанный проект `evwvbozhfsprcabrfefe`. Развёрнута версия 1 `delete-account`. Адрес по умолчанию для почтовых ссылок в Supabase сейчас `http://localhost:3000`. Перед публичным выпуском нужно проверить подтверждение регистрации и восстановление пароля с рабочим HTTPS-адресом. [Настройка облака](../ОБЛАКО_НАСТРОЙКА.md)
- Open Food Facts получает введённый пользователем текст поиска или распознанный штрихкод. Указан источник и ODbL, собственные фото продуктов сервиса не используются. WebView добавляет идентификатор FORGE к User-Agent. Журнал офлайн не зависит от API и допускает ручной ввод. [Документация Open Food Facts](https://openfoodfacts.github.io/openfoodfacts-server/api/)

## Что осталось

1. На двух тестовых телефонах обновить предыдущий APK с совместимой подписью и заполненным синтетическим дневником. Проверить программы, запись незавершённой тренировки, фотографии, питание и вес. Сверить после авиарежима, принудительной остановки и повторного запуска. Системный экспорт и импорт JSON проверить отдельным файлом.
2. Выполнить тренировку из программы до истории, затем проверить Back аппаратной кнопкой и обоими жестами. Повторить с клавиатурой, открытой карточкой, изменённым черновиком, поворотом, крупным шрифтом и TalkBack. Сверить таймер после блокировки и в режиме экономии энергии.
3. Проверить сканер с EAN-13, EAN-8 и UPC. Повторить без сети, без разрешения, после отзыва, при плохом освещении, повороте и быстром закрытии. При отсутствии данных внести продукт вручную и сверить единицы.
4. Двумя выделенными аккаунтами на Android проверить вход, выход, отмену, повторный вход, истёкшую сессию, восстановление и конфликт. Повторить удаление с отдельным тестовым аккаунтом из приложения, сверить сохранение локального журнала. Проверить рабочий email callback.
5. Подтвердить контакты, декларации конфиденциальности, происхождение изображений и юридическую приёмку. Подготовить ключ и отдельный закрытый трек по [чек-листу магазинов и беты](STORE_RELEASE_CHECKLIST.md). Для подписи и публикации требуются действия владельца.
