## Найденная и исправленная ошибка

`n10ValidateRestore` проверял только первые 50 тренировок/продуктов. Тест с null на 52-й позиции показал замену дневника некорректными данными. Теперь обход полный; дополнительно отклоняются повреждённые структуры программ/рецептов, отрицательные/нечисловые значения, нецелые повторы. Пользовательские записи не мигрируются и не удаляются: отклоняется весь некорректный импорт. Старые архивы с некорректными значениями потребуют исправления копии архива вручную.

## Автоматические проверки

- `node scripts/check-web.mjs`: синтаксис 10 inline-блоков + локальный exercise-art.js.
- `node scripts/check-art.mjs`: 556 точных привязок, наличие файлов, различные движения плеч, личное изображение, fallback и экранирование.
- `node scripts/browser-regression.cjs`: мобильный каталог, кнопки, добавление в тренировку/программу, reload, совпадение исходного каталога, отсутствие горизонтального переполнения и ошибок.
- `node scripts/core-regression.cjs`: **18 сценариев**, перечисленных в журнале; реальная страница с Android-подобным HTTPS origin, все внешние запросы блокируются. Временный профиль; реальные данные пользователя не используются. Обработчики вызываются программно и частично через DOM: это браузерная интеграционная проверка, не Android UI test. AndroidBridge подменён только для перехвата экспорта.
- Gradle: `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug`. Unit-тестов Kotlin нет (**NO-SOURCE**).
- Workflow дополнен браузерными регрессионными проверками. Playwright закреплён на 1.62.1; установка Chromium выполняется в CI.

## Android: структура и ограничения

Manifest: launcher Activity exported=true, CAMERA и INTERNET, камера необязательна, cleartext запрещён, Android backup выключен. Отдельное разрешение на общее хранилище не требуется: используется системный выбор/создание документа. WebView локальный через WebViewAssetLoader, JavaScript и DOM storage включены; file access и смешанный контент выключены. Камера выдаётся только для локального origin. Это статический обзор, а не динамический security-аудит.

Данные хранятся в localStorage `forge_v2`. Это историческое имя ключа, не версия приложения. Миграция/сброс не выполнялись. Удаление приложения удаляет локальные данные; обновление требует той же подписи. Debug-ключ CI может меняться между runner; пока нет настроенного стабильного release-ключа. В тестовые Releases загружается APK с сохранённой локальной debug-подписью.

## Что требуется до заявления «стабильный Android-релиз»

1. На телефоне: обновить поверх 10.0.1 с резервной копией; убедиться, что дневник сохранён.
2. Без сети: полный цикл программы/тренировки/питания, закрытие процесса и повторный запуск.
3. Системные JSON/CSV export и restore, разрешение камеры, Back, поворот и возврат из фона.
4. Проверка всех рисунков и корректности техники; доступность и масштаб текста.
5. Отдельная настройка постоянной подписи и, при необходимости, Supabase.

Вывод: подтверждена работоспособная основа FORGE10 в пределах перечисленных автоматических сценариев. Полностью стабильной Android-версией до проверки устройства её называть нельзя. Google Play и реальные платежи не подключались.
