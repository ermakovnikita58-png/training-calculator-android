# FORGE Training — мастер-задание для Codex и дорожная карта

Дата: 31 октября 2026 г.

## Контекст
Развиваем EXISTING FORGE Training — Android-дневник силовых тренировок и питания. Не создавать очередное приложение с нуля и не удалять функциональность под видом упрощения.

GitHub: `ermakovnikita58-png/training-calculator-android`
В текущем `main` на момент аудита: `.github/workflows/build.yml` и старый `forge-training-v2-project.zip`. Последняя обнаруженная успешная GitHub Actions сборка датирована 29 октября 2026 года; она не доказывает готовность FORGE 10.

В библиотеке проекта ChatGPT «Дневник калькулятор» есть артефакты:
- `forge-training-10-complete-kit.zip` (полный комплект);
- `forge-training-10-android-project.zip` (Android-исходники);
- `forge-training-10.html` (HTML-версия);
- `forge-build.yml` (предлагавшийся workflow).

Если эти файлы не предоставлены в рабочей среде Codex, честно сообщи о блокировке миграции и запроси архив. Не объявляй FORGE 2 актуальной версией. Не генерируй заново приблизительную копию FORGE 10.

## Роль
Ты senior Android engineer, технический архитектор, QA lead и продуктовый разработчик. Цель — превратить FORGE 10 в стабильное мобильное приложение для Android, затем развивать его в FORGE 11. Работай итерациями, проверяй результат после каждого этапа, пиши код, тесты и документацию, создавай отдельную ветку / pull request, если есть право записи. Не отправляй в продакшен и не публикуй в Google Play без явного подтверждения.

## Обязательные функции, которые надо сохранить и проверить
- Программы тренировок: создание/редактирование, расписание дней недели, упражнения и подходы.
- Дневник активной тренировки: ввод веса, повторений, RPE, отметка завершения подхода в одно нажатие, история предыдущих результатов, заметки.
- Таймер отдыха общий и индивидуальный; калькулятор дисков и силовые инструменты.
- Силовые калькуляторы 1ПМ/5ПМ и периодизация/циклы; не путать оценочный 1ПМ с гарантированным максимумом.
- Библиотека упражнений с поиском/фильтрами, пользовательские упражнения и собственные иллюстрации; 556 вариантов из прежнего плана требуют инвентаризации, а не слепого заявления о точном числе.
- Статистика тренировок, рекордов, тоннажа, массы тела и динамики.
- Питание: учёт калорий и БЖУ, продукты, рецепты, шаблоны/повтор еды, штрихкоды при доступности камеры/данных.
- Офлайн-работа, локальное сохранение, JSON backup/restore, CSV экспорт. Облачная синхронизация — опционально после настройки инфраструктуры.

## Порядок выполнения (не пытайся внедрить всё одним коммитом)

### Этап 0. Аудит и восстановление основы — обязательно первый
1. Изучи дерево репозитория, файл `.github/workflows/build.yml`, артефакты FORGE 10, модель хранения данных, WebView/HTML или Kotlin компоненты.
2. Составь `docs/AUDIT.md`: что реально работает, что частично, чего нет, P0/P1/P2, угрозы потери пользовательских данных.
3. Зафиксируй эталон текущих возможностей (регрессионный чек-лист) и backup исходников. Не перезаписывай основную ветку без PR.
4. Если FORGE 10 недоступен, останови перенос и явно перечисли нужные файлы; разрешено отдельно исправлять workflow, но нельзя выдавать продукт за новую версию.

### Этап 1. Восстановление Android-проекта и APK — P0
1. Перенеси именно FORGE 10 в рабочий проект. Предпочитай минимальное изменение существующей архитектуры, чтобы получить работоспособную сборку; не переписывай всё сразу на Compose.
2. Разложи файлы проекта по стандартным папкам, положи source files в репозиторий; ZIP может остаться архивным input, но это не замена управляемому исходному коду.
3. Исправь текущий workflow: он выбирает `find ... '*.zip' | head -n 1`, что может собирать FORGE 2 вместо FORGE 10. Убери неопределённый выбор, используй явный исходный каталог/Gradle wrapper или конкретный архив с валидацией версии.
4. Проверь корректные версии JDK, Gradle, AGP, Android SDK и совместимость; для нового приложения Google Play targetSdk не ниже API 36 согласно правилам от 31.08.2026. Не обновляй версии вслепую; проверь матрицу совместимости.
5. `assembleDebug`, `test`, статический анализ; artifact `FORGE-debug.apk` в GitHub Actions. Если имеется безопасная инфраструктура подписи, отдельно release APK/AAB, без ключей и токенов в Git.
6. Исправь Android Back, WebView file access, intent/permissions камеры, safe-area, возврат из фона, rotation; проверь работу без интернета.
7. Создай `README.md` с пошаговым руководством: clone/build/install APK без ПК через GitHub Actions artifact и с ПК по ADB.

### Этап 2. Надёжность хранения данных и тесты — P0
1. Определи текущую схему данных и разработай версионированные миграции. Пользовательские тренировки и питание нельзя безвозвратно терять при обновлении.
2. Сохрани офлайн-first: любые базовые записи должны работать без регистрации и сети. Локальная база — источник истины на устройстве. Если есть причины мигрировать с localStorage, предложи SQLite/Room или надёжное IndexedDB решение; миграция должна быть обратимо протестирована на копиях.
3. Валидация значений (вес >= 0, целые повторения, корректные даты и макросы), защита от дубликатов и багов быстрых нажатий.
4. Тесты функций 1ПМ/5ПМ, прогрессии веса, дневной КБЖУ, импорт/экспорт. Тестируй неверный JSON, отмену импорта, большие объёмы истории, восстановление после сбоя и обновление поверх старой версии.
5. UI smoke-тесты: создать программу, запустить тренировку, записать подход, завершить, перезапустить, проверить сохранение; внести приём пищи, экспортировать и восстановить.

### Этап 3. UX/UI — P1
Оригинальный визуальный стиль FORGE: тёмный графит, светлый текст, лаймовый акцент, собственная графика; не копировать экраны/ассеты конкурентов. Отдельные экраны: Главная, Тренировка, Программы/Каталог, Питание, Прогресс, Профиль/Настройки. Не делать одну длинную страницу.
- Активная тренировка: крупные элементы управления одной рукой, текущий/предыдущий подход, запись одним касанием, видимый таймер, защита от потери черновика.
- Редактор программ: дни недели, drag/reorder, упражнения, повторения/вес, редактирование без browser prompt.
- Каталог: мышцы, оборудование, поиск, техника и заметки; осмысленные изображения или честные заглушки.
- Питание: быстрый повтор рационов и избранного, рецепт/порция, итог КБЖУ.
- Доступность: масштабирование текста, TalkBack, контраст, большие touch targets, русская локализация; затем английская.

### Этап 4. Новые функции — P1/P2
- Типы подходов: разминка/рабочий/дроп/до отказа; RPE/RIR, суперсеты.
- Рекомендовать следующий вес на основе истории и диапазона повторений, с ограничением роста и ОБЯЗАТЕЛЬНЫМ подтверждением пользователя; никогда не изменять завершённые подходы.
- Личные рекорды, volume, estimated 1RM по упражнению, нагрузка мышечных групп; измерения тела.
- Каталог 500+ корректно названных упражнений с авторскими/лицензированными данными. Не копировать без разрешения базы GymUp/других приложений, фотографии и инструкции.
- База продуктов через лицензированные источники; Open Food Facts при наличии связи, проверка этикетки, офлайн сохранение избранных продуктов. Не копировать платную базу Коробова без лицензии.
- Сканирование штрихкода на реальном Android, graceful fallback при отсутствии товара или сети.
- Health Connect и дополнительные функции — только после стабильного релиза и отдельной проработки permissions.

### Этап 5. Аккаунт и синхронизация — после P0
- Offline guest mode по умолчанию.
- Если пользователь предоставит Supabase/Firebase проект: email auth, Google OAuth, верная обработка сессии, конфликты синхронизации, RLS, удаление аккаунта и данных; тест двух устройств.
- Никогда не клади API secrets/service-role keys в клиент, лог или Git. Не выдавай прототип с пустыми конфигурациями за рабочее облако.
- Избегай потери локальных данных при входе/выходе; cloud restore только после подтверждения при конфликте.

### Этап 6. Монетизация и Google Play — отдельно после стабильной beta
- Freemium: бесплатные тренировки, программы, базовый дневник питания и история. FORGE PRO — расширенная аналитика/умные подсказки/синхронизация при работающем backend. Не блокируй доступ к пользовательским данным при отмене подписки.
- Подготовь архитектуру Google Play Billing для помесячной/годовой подписки и возможной одноразовой покупки; не делай фиктивные платежи. Тестируй sandbox, restore purchases, отмены и серверную проверку entitlement.
- AdMob — только опционально и не во время тренировки; пользовательский выбор приватности, согласие для рекламы там, где требуется.
- Политика конфиденциальности, Data Safety, Health apps declaration, удаление аккаунта и политика хранения данных; release AAB, иконки, screenshots, Play listing.
- Не публикуй и не трать деньги без отдельного подтверждения владельца.

## Критерии приёмки
- Исходная версия FORGE 10 доступна для сравнения и перенесена без потери функциональности.
- CI зелёный и действительно компилирует FORGE 10/11, а не старый ZIP; доступен скачиваемый debug APK.
- APK устанавливается на реальный Android; минимальный сценарий тренировки и питания работает без интернета.
- Данные переживают перезапуск/обновление; JSON backup + restore проходят тесты без скрытой потери истории.
- Нет фиктивных логинов, платежей, неверифицированного «AI», нелицензированных чужих изображений и баз.
- Сборка на Google Play соответствует актуальным требованиям (API 36+ для новых обычных Android-приложений с 31.08.2026), есть план проверок политики.
- Для каждого этапа: список изменённых файлов, команды тестирования, результаты, нерешённые риски и ссылка на PR/artifact. Не отмечай задачу Done, если проверка не выполнялась.

## Формат отчёта Codex после первого запуска
1. Что действительно лежит в GitHub и что найдено из FORGE 10.
2. Таблица: уже работает / сломано / отсутствует.
3. Критические ошибки и угрозы данным.
4. Какие файлы изменены и какие тесты прошли, с логами.
5. Ссылка на PR и скачиваемый APK, если сборка прошла.
6. Если архив FORGE 10 недоступен — один чёткий блокер с точным именем нужного ZIP; не продолжать миграцию на основании FORGE 2.

## Дорожная карта
**P0 / Выпуск работающего Android:** аудит, импорт FORGE 10, корректный CI, APK, офлайн-хранение, миграции, регрессия.

**P1 / Качество ежедневной работы:** быстрые подходы, таймер, программы, суперсеты, RPE/RIR, аналитика, питание и рецепты, выверенный интерфейс.

**P2 / Публичная бета:** авторизация и синхронизация только после backend-конфигурации, crash-reporting с согласием, локализация, лицензии, политика приватности, тестирование на телефонах.

**P3 / Монетизация и Play:** подписки, восстановление покупок, опциональная реклама, подписанный AAB, Store listing, тестовая публикация после разрешения.
