# FORGE Training — облачный аккаунт и вход через Google

Проверочная Android-сборка 11.4.1 (26) использует проект Supabase `forge` с идентификатором `evwvbozhfsprcabrfefe` и адресом `https://evwvbozhfsprcabrfefe.supabase.co`. Адрес и публичный publishable key заданы для новых установок Android. Сохранённые настройки собственного проекта продолжают использоваться. Вход по почте доступен для выбранного проекта, а нативный вход Google привязан к проекту FORGE.

В проекте применены `supabase-schema.sql` и `supabase/migrations/20261110000000_snapshot_revision.sql`. В `public.forge_snapshots` хранится одна копия на Supabase `user.id`. RLS ограничивает чтение и запись владельцем. Прямые SQL-проверки с двумя временными идентификаторами на этом проекте прошли с откатом. Вход с двумя настоящими аккаунтами проверяется отдельно по шагам ниже.

## Настройка Google владельцем проекта

1. В существующем проекте Google Cloud открой **Google Auth Platform → Branding**. Проверь название и контакт приложения. Если Google Cloud показывает экран **Terms of Service**, прими решение об условиях в аккаунте владельца. Для режима **External → Testing** в **Audience → Test users** добавь два выделенных аккаунта для проверки. Для входа используются базовые данные аккаунта Google `openid`, `email` и `profile`. [Google Auth Platform](https://console.cloud.google.com/auth/clients)
2. В **Clients** открой существующий клиент типа **Web application**, который используется для FORGE. Если его ещё нет, создай **Web application**. В **Authorized redirect URIs** добавь `https://evwvbozhfsprcabrfefe.supabase.co/auth/v1/callback`. Сохрани действующие URI и **Authorized JavaScript origins** веб-версии. [Инструкция Supabase по Google OAuth](https://supabase.com/docs/guides/auth/social-sign-in/auth-google?platform=android&queryGroups=platform)
3. В **Clients → Create client → Android** зарегистрируй пакет `ru.trainingcalculator.app` и SHA‑1 `63:BC:E1:5E:7C:80:14:81:85:03:E1:AF:4D:92:C7:63:9A:18:3D:97`. Это отпечаток проверочной debug-подписи, применяемой к скачиваемому APK FORGE. Для другого ключа сборки зарегистрируй соответствующий отпечаток. Его можно получить командой `apksigner verify --print-certs FORGE-Training-11.4.1-debug.apk`.
4. В **Supabase → Authentication → Sign In / Providers → Google** включи провайдер. В **Client IDs** укажи Web Client ID первым и добавь Android Client ID через запятую. Сохрани ранее зарегистрированные ID. В **Client Secret** используй значение для первого Web Client ID, оставь **Skip nonce check** выключенным. Web Client Secret вводится только в Supabase. Существующие **Site URL** и **Redirect URLs** веб-версии остаются в **Authentication → URL Configuration**. [Провайдер Google проекта FORGE](https://supabase.com/dashboard/project/evwvbozhfsprcabrfefe/auth/providers?provider=Google)
5. В проверочном APK открой **Профиль → Войти через Google → Настроить облако (Supabase)**. Вставь публичный **Web Client ID** в поле **Google Web Client ID**, сохрани его и снова нажми **Войти через Google**. Android покажет системный выбор аккаунта. FORGE использует веб-идентификатор для запроса ID token, а Supabase проверяет токен и выдаёт свою сессию. [Android Credential Manager](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation)

Если FORGE распространяется через Google Play, зарегистрируй также SHA‑1 из **Play Console → Protected with Play → Play Store protection → Manage Play app signing → App signing key**. В этой проверке доступен сертификат debug APK. [Подпись приложений в Google Play](https://support.google.com/googleplay/android-developer/answer/9842756)

## Проверка на телефоне

1. До входа добавь тестовую запись в локальный дневник. Войди через Google и убедись, что запись осталась, а автосохранение выключено. Для первой синхронизации выбери **Отправить в облако** или **Скачать из облака**. После ручной отправки или восстановления можно включить автообмен. Он останавливается при изменении ревизии облачной копии на другом устройстве.
2. Отправь первую тестовую копию с аккаунта А. Выйди и войди с аккаунта Б. Убедись, что аккаунту Б доступна только его собственная копия. Проверь, что локальный дневник доступен после выхода и в авиарежиме.
3. Для проверки связывания создай копию под аккаунтом с подтверждённой почтой, которая совпадает с подтверждённым адресом тестового аккаунта Google. Выйди, затем войди через Google. Сверь **User UID** в **Supabase → Authentication → Users** и доступ к прежней копии. Автоматическое связывание выполняет Supabase. [Supabase Identity Linking](https://supabase.com/docs/guides/auth/auth-identity-linking)
4. Закрой системный выбор аккаунта и снова нажми кнопку. Повтори с отключённым интернетом. После успешного входа перезапусти FORGE, открой аккаунт и проверь доступ к копии. После выхода перезапусти приложение и проверь, что сеанс закрыт, а дневник доступен локально.

Вход Google на устройстве требует включённого провайдера и настроенных клиентов Google в проекте владельца. Проверки обмена сессией и ошибок в автоматических тестах используют тестовые ответы.

## Аккаунт, офлайн-доступ и удаление

- Вход по почте и восстановление пароля доступны из **Профиль → Войти по почте**. Для своего Supabase-проекта укажи его URL и публичный ключ в **Настроить облако** и примени оба SQL-файла. Сайт на HTTPS использует существующий веб-поток OAuth с перенаправлением. HTML, открытый через `file://` или `content://`, может столкнуться с ограничениями CORS. [Supabase Auth по почте](https://supabase.com/docs/guides/auth/passwords)
- В Android токены сессии Supabase защищены Android Keystore. Токен Google используется нативно для обмена на сессию Supabase. Облачная копия передаётся через TLS. Администратор проекта Supabase имеет доступ к данным в базе.
- Локальные записи и пользовательские фотографии доступны офлайн. Фото могут входить в облачную копию в пределах лимита 6 МБ. Для переноса можно также экспортировать JSON.
- **Удалить облачный дневник** удаляет копию в аккаунте. Для кнопки **Удалить аккаунт** требуется серверная функция `supabase/functions/delete-account/index.ts`. Для её отдельного развёртывания используй `supabase functions deploy delete-account --project-ref evwvbozhfsprcabrfefe`. Сервисный ключ используется в окружении Supabase. При удалении пользователя Supabase удаляет связанную облачную копию, а локальный дневник остаётся на устройстве.
