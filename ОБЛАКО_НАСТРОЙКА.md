# FORGE Training 10 — подключение реального облака

В приложении доступна **настоящая** интеграция по HTTPS с Supabase Auth / PostgREST. До ввода настроек работает только локальное сохранение — это нормально. Своего облачного проекта и ключей в поставке нет.

## С телефона

1. Открой https://supabase.com/dashboard и создай свой проект (название и пароль базы выбираешь сам).
2. В **SQL Editor** выполни скрипт `supabase-schema.sql` из архива. Он создаёт одну таблицу `forge_snapshots` с RLS, которая разрешает пользователю видеть и менять **только собственную запись**.
3. В **Project Settings → API** (либо **Connect / API Keys**) найди URL вида `https://<project-id>.supabase.co` и **publishable key** (`sb_publishable_...`) или legacy `anon` key. **Никогда не копируй service_role/secret key в HTML, GitHub или форму приложения.**
4. В FORGE выбери **Профиль → Войти → Настроить облако** и введи URL и публичный ключ. После сохранения зарегистрируй почту и пароль. Если включено подтверждение почты, подтверди ссылку из письма.
5. Для первой синхронизации выбери **«Отправить в облако»** (если текущий телефон содержит нужную историю) или **«Скачать из облака»** (если это новый телефон). Затем можно включить **автосохранение**. Оно проверяет, что другая версия облака не изменилась, и останавливается при конфликте.
6. Чтобы удалить облачный дневник без удаления аккаунта, используй кнопку **«Удалить облачный дневник»**.

**Важно:** HTML, открытый напрямую как `file://` или `content://`, может блокировать CORS на некоторых браузерах. Для надёжной авторизации используй **Android APK** (встроенная локальная HTTPS-среда через WebViewAssetLoader) или опубликованную на HTTPS PWA. Для тестирования из локального браузера возможны ограничения origin `null`.

## Google-аккаунт

Google OAuth в данной версии поддерживается **только в PWA на опубликованном HTTPS-домене** после настройки Google-провайдера Supabase и Redirect URLs. В Android WebView Google OAuth намеренно отключён: встроенный WebView не подходит для этого потока. В Android-проекте полноценно предусмотрен вход по почте/паролю. Чтобы добавить вход через Google на Android, следует реализовать нативный Credential Manager и надёжный обмен токенов с Supabase — это отдельная интеграция с собственными OAuth-клиентами и подписью приложения.

## Удаление аккаунта (включая Auth)

Приложение содержит кнопку удаления аккаунта, но для её работы надо **развернуть** серверную функцию `supabase/functions/delete-account/index.ts`. Сервер использует сервисный ключ только как окружение Supabase. Данные дневника каскадно удаляются из `forge_snapshots` вместе с пользователем. После удаления учётной записи локальный дневник на телефоне остаётся: его можно удалить отдельно в профиле.

**Пример через Supabase CLI** (когда будет доступен компьютер либо облачная среда): `supabase functions deploy delete-account --project-ref YOUR_PROJECT_REF`. Не публикуй service_role в репозитории.

## Безопасность и ограничения

- Облачная информация отправляется через TLS, но не шифруется сквозным пользовательским ключом. Администратор собственного проекта Supabase имеет доступ к данным в базе.
- Сессионный токен хранится локально в хранилище приложения; защищай доступ к устройству. Пароль не записывается в дневник и не попадает в JSON-бэкап.
- Встроенные изображения упражнений являются файлами приложения, не персональными данными. Загруженные тобой фото сохраняются в локальном дневнике и могут входить в облачный JSON, если укладываются в лимит 6 МБ.
- Синхронизация требует интернета. При офлайн-тренировке записи остаются локально, затем можно отправить их в облако.
- Важные изменения перед переносом устройства следует дополнительно сохранять через экспорт JSON.
- Перед коммерческим выпуском протестируй RLS под **двумя независимыми пользователями**, особенно SELECT/UPDATE/DELETE.
